# Lesson 09 — The Effects Chain: Saturator → Delay → Reverb

After the synth and granular engines are blended (lesson 05, step 10), the
mix runs through three effects **in series, in place** (each reads and writes
the same buffer):

```
blend ──▶ SATURATOR ──▶ EUCLIDEAN DELAY ──▶ LUSH REVERB ──▶ ×0.7 ──▶ out
```

**Why this order?** It's the classic chain: *distort the dry sound first,
then smear it in time.* Saturating after the reverb would distort the reverb
tail into mush; delaying before saturation would distort every echo
differently. The order is a musical decision, not an accident.

Four files in `Source/dsp/` — one per effect, plus a stub:

| File | Effect | Status |
|---|---|---|
| `Saturator.{h,cpp}` | 6-mode distortion | Full |
| `EuclideanDelay.{h,cpp}` | Tempo-synced, rhythm-gated delay | Full (pattern fixed at 3-in-8) |
| `LushReverb.{h,cpp}` | Shimmer reverb | Full (width fixed at 1.0) |
| `FFTConvolver.{h,cpp}` | IR convolution reverb | **Compiled but unwired stub** |

All four obey the audio-thread contract: `process()` does no allocation,
takes no locks, uses no static locals.

## Saturator: 6 ways to get dirty

```cpp
enum class Algorithm
{
    None,       // 0 — bypass
    Bitcrush,   // 1 — reduce bit depth: lo-fi crunch
    RateCrush,  // 2 — reduce sample rate: aliasing grit
    Wavefold,   // 3 — fold the waveform back on itself past ±1: harsh, brassy
    Phase,      // 4 — all-pass phase smear: subtle movement
    Tape,       // 5 — soft saturation: warm glue
    Tube        // 6 — harder asymmetric saturation: aggressive warmth
};
// Enum order matches the editor combo:
// "None, Bitcrush, Rate Crush, Wavefold, Phase, Tape, Tube"
```

Same contract as the synth algorithms: the `SAT_ALGO` combo-box order must
match the enum. Controls: `SAT_DRIVE` (0–24 dB of drive into the shaper),
`SAT_MIX` (dry/wet), plus an output trim.

**The static-local bug, again (DEVIATIONS.md item 23):** the Phase
algorithm's all-pass filter used `static float lastIn/lastOut` *inside the
per-sample loop* — shared across channels, never reset, not thread-safe
(the exact same disease as the synth's Analog Hat in lesson 07). The fix is
identical in spirit: member arrays indexed per channel, cleared by `reset()`:

```cpp
// All-pass state for the Phase algorithm.
// BUG FIX vs sketch: the sketch used `static float lastIn/lastOut` inside
// the per-sample loop — shared across channels, never reset, not
// thread-safe. These member arrays are indexed per channel (modulo 2) and
// cleared by reset().
float phaseStateIn[2] = {};
float phaseStateOut[2] = {};
```

If you take one rule from this whole series: **mutable `static` locals have
no place in per-sample DSP.** State belongs to the instance (per channel) or
the voice.

## Euclidean delay: rhythm-gated echoes

A normal tempo-synced delay repeats everything you play, every N beats. This
one adds a twist: the **feedback path is gated by a Euclidean rhythm** — a
pattern generated by the **Bjorklund algorithm** that distributes `pulses`
hits as evenly as possible across `steps` beats. 3 pulses in 8 steps, for
example, gives the classic `X..X..X.` tresillo-ish lilt — the echoes
themselves play a rhythm.

Parameters: `DELAY_DIV_NUM`/`DELAY_DIV_DEN` set the delay time as a musical
division — `noteSeconds = (60/bpm) × (4·num/den)` (so 1/4 at 120 BPM = 0.5 s);
`DELAY_FB` (0–0.95, never 1.0 — full feedback would ring forever and is one
`NaN` away from disaster); `DELAY_MIX`.

**The per-sample gating bug (item 24)** — the most instructive in this
lesson. The sketch advanced the Euclidean step **once per sample**:

```cpp
// MANDATORY BUG FIX vs sketch: the sketch advanced euclideanStep once
// per SAMPLE ...
if (samplesIntoPeriod >= delaySamples)
{
    samplesIntoPeriod = 0;
    ...
    euclideanStep = (euclideanStep + 1) % pattern.size();
}
++samplesIntoPeriod;
```

Think about what per-sample stepping means: at 44100 Hz with a 0.5 s delay,
the pattern would advance 44,100 times per second — through an 8-step
pattern 5,500 times a second. The "rhythm" becomes ultrasonic noise; the
gate is effectively random. The fix: a `samplesIntoPeriod` counter, and the
pattern step advances **once per delay period**. The rhythm now actually
*is* a rhythm — one gate decision per echo.

Two more fixes in this file: the delay buffer was hardcoded to 96 kHz worth
of samples (item 25 — at 192 kHz sessions it would be too short; it's now
sized from the actual sample rate with margin for 2 seconds), and divisions
are guarded against zero denominators.

**Documented simplification:** the pattern is fixed at 3-pulses-in-8-steps
(`delay.setEuclideanPattern(3, 8)` in `prepareToPlay`) — there's no
parameter or UI for the rhythm shape yet. It sounds good; configurability
waits for the GUI work to resume.

## Lush reverb: Freeverb + shimmer

`LushReverb` wraps JUCE's own `juce::Reverb` (a classic Freeverb-style
algorithm: combs + allpasses) and adds one cheap trick for "lushness": a
**slow 0.5 Hz LFO that gently nudges the damping parameter**. Damping
controls how fast high frequencies decay in the tail; wobbling it makes the
tail shimmer and breathe instead of sitting static.

Implementation notes:

- `setParameters(room, damp, mix, width)` stores the values in members; the
  actual `juce::Reverb::Parameters` struct is rebuilt **once per block**
  (item 26 — the sketch redundantly rebuilt it in multiple places).
- The LFO is applied once per block, not per sample — modulation at 0.5 Hz
  doesn't need 44,100 updates a second.
- Mono input is upmixed through a member scratch buffer sized in `prepare()`
  (same allocate-once discipline as everything else).
- **JUCE 9 API drift (item 33):** the sketch called
  `juce::Reverb::setEnabled()` — which **doesn't exist in JUCE 9**. It was
  simply removed. When you port code between JUCE versions, the compiler is
  your friend: "no member named X" means "check the new API."
- **Width is fixed at 1.0** (full stereo) — no parameter allocated yet.

## FFTConvolver: the honest stub

```cpp
// Thin wrapper around juce::dsp::Convolution for reverb-style IR processing.
// process() is a no-op bypass until an impulse response is loaded successfully.
```

This wraps `juce::dsp::Convolution` (partitioned FFT convolution — the
efficient way to run very long reverbs). But: **nothing loads an impulse
response into it, and no parameter drives it** — `process()` is a bypass
until `loadImpulseResponse()` succeeds, which nothing calls. It compiles, it
works, it's just unwired.

**Why keep it?** Because the *plumbing* is done and correct — including the
JUCE 9 API fix (item 34): the sketch used the
`Convolution::loadImpulseResponse(AudioBlock)` overload, which was **removed
in JUCE 9**; the fix uses the `AudioBuffer&&` overload. When the IR-loading
UI arrives, this file is ready. An honest, compiling, tested stub with a
comment beats a TODO in a header.

## Check your understanding

- Chain order is musical: **saturate → delay → reverb**, then ×0.7 safety
  gain; all in-place, all allocation-free.
- Saturator has **6 algorithms + bypass** (`SAT_ALGO` order matches the
  enum); the Phase algorithm's filter state is per-channel **members**, not
  `static` locals.
- The Euclidean delay gates feedback with a **Bjorklund rhythm**; the gate
  advances **once per delay period** (the sketch's per-sample stepping was
  ultrasonic nonsense).
- Delay time = `(60/bpm)·(4·num/den)`; feedback is capped at 0.95; the buffer
  is sized from the real sample rate.
- Lush reverb = `juce::Reverb` + a **0.5 Hz LFO on damping**; params rebuilt
  once per block; `setEnabled()` doesn't exist in JUCE 9.
- `FFTConvolver` is a correct, compiling, **unwired** stub — bypasses until
  an IR is loaded.
